# 认证接口

## 注册

`POST /api/auth/register`

### 请求示例

```json
{
  "username": "demo_user",
  "password": "demo-password",
  "nickname": "Demo",
  "email": "demo@example.com",
  "phone": ""
}
```

### 请求字段说明

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| username | string | 是 |  | 用户名，3-32 位 |
| password | string | 是 |  | 登录密码，最小长度由 `auth.password_min_length` 控制，最大 72 字节 |
| nickname | string | 否 | username | 昵称，最大 64 字符 |
| email | string | 否 |  | 邮箱，最大 128 字符 |
| phone | string | 否 |  | 手机号，最大 32 字符 |

### 安全字段

| 项目 | 字段 |
|------|------|
| 请求签名字段 | username, password, nickname, email, phone |
| 请求加密字段 | password, email, phone |
| 响应签名字段 | token, expiresAt, user.email, user.phone |
| 响应加密字段 | token, user.email, user.phone |

### 响应示例

```json
{
  "status": true,
  "code": 1100,
  "message": "创建成功",
  "data": {
    "token": "jwt-token",
    "expiresAt": 1790841600,
    "user": {
      "id": "778919762005200896",
      "shardNo": 896,
      "username": "demo_user",
      "nickname": "Demo",
      "email": "de***o@example.com",
      "phone": "138****0000",
      "avatar": "",
      "status": 1,
      "lastLoginAt": "2026-06-02 12:00:00",
      "lastLoginIp": "127.0.0.1",
      "createdAt": "2026-06-02 12:00:00",
      "updatedAt": "2026-06-02 12:00:00"
    }
  }
}
```

`data.user` 字段结构与 [用户接口](用户接口.md) 的当前用户资料一致，包含 `shardNo` 分片号；`id` 为字符串形式的雪花 ID，避免前端 JS 安全整数精度丢失。

注册入口可通过 `auth.register_rate_limit` 配置 Redis 限流，计数、窗口 TTL 和超限锁通过同槽 Lua 原子更新，触发后返回业务码 `1003`。注册成功或触发限流时会 best-effort 投递 `auth.security` 脱敏风控事件。

注册失败时常见业务码：

| 业务码 | 状态含义 |
|------|----------|
| 1001 | 请求字段或密码长度不合法 |
| 1003 | 请求过于频繁 |
| 20005 | 注册入口已关闭 |
| 21002 | 用户名或登录身份已存在 |

注册成功会按身份类型写入登录身份索引：`username` 必写入 `user_identity_username.identity_value`，`email` 和 `phone` 非空时分别以 HMAC 写入 `user_identity_email.identity_hash`、`user_identity_phone.identity_hash`，后续三方身份写入 `user_identity_oauth(provider, identity_value)`。用户与身份索引写入保持在同一数据库事务中，Redis 会话创建失败会回滚事务，避免留下已占用身份但客户端未取得登录态的半注册账号。`user` 主表只保存邮箱和手机号的 AES-GCM 密文、HMAC 查询哈希和脱敏展示值；响应中的 `user.email/user.phone` 也是脱敏值。

## 登录

`POST /api/auth/login`

### 请求示例

```json
{
  "identityType": "email",
  "identityValue": "demo@example.com",
  "password": "demo-password"
}
```

### 请求字段说明

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| identityType | string | 是 |  | 登录身份类型：`username`、`email`、`phone` |
| identityValue | string | 是 |  | 登录身份值；`username` 为 3-32 位，`email` 最大 128 字符，`phone` 最大 32 字符 |
| password | string | 是 |  | 登录密码，最大 72 字节 |

### 安全字段

| 项目 | 字段 |
|------|------|
| 请求签名字段 | identityType, identityValue, password |
| 请求加密字段 | identityValue, password |
| 响应签名字段 | token, expiresAt, user.email, user.phone |
| 响应加密字段 | token, user.email, user.phone |

### 响应说明

响应结构与注册接口一致。失败时常见业务码：

| 业务码 | 状态含义 |
|------|----------|
| 1001 | 请求字段不合法 |
| 20001 | 账号、密码或账号状态不可登录；统一文案避免泄露账号状态 |
| 1003 | 请求过于频繁 |

登录入口可通过 `auth.login_rate_limit` 配置 Redis 限流，默认建议按 IP 和登录身份两个维度保护；计数、窗口 TTL 和超限锁通过同槽 Lua 原子更新。密码登录只接受 `username/email/phone`，三方 `oauth` 身份由后续 provider 回调在完成 token 校验后绑定或登录，不能复用密码登录入口。登录成功、账号密码失败、用户禁用或触发限流时会 best-effort 投递 `auth.security` 脱敏风控事件，`session_hash` 是稳定 `sid` 的不可逆哈希，不会写入明文会话标识或 token。

## 刷新令牌

`POST /api/auth/refresh`

### 请求头

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| Authorization | string | 是 |  | `Bearer <token>` |

### 安全字段

| 项目 | 字段 |
|------|------|
| 请求签名字段 | 不参与签名 |
| 请求加密字段 | 不参与加密 |
| 响应签名字段 | token, expiresAt |
| 响应加密字段 | token |

### 响应说明

响应结构与登录接口一致。每次登录生成稳定 `sid`，每个访问 token 生成唯一 `jti`。刷新通过同槽 Redis Lua 在同一 `sid` 下原子校验认证版本和完整旧 token，再覆盖为新 `jti` 的 token；同一个旧 token 最多成功刷新一次，并发失败请求返回业务码 `20004`。刷新与退出并发时，退出始终按稳定 `sid` 删除当前 token；若退出先完成，刷新的完整旧 token CAS 必然失败。每个用户最多保留 8 个有效会话，超出时原子淘汰最早过期会话。

## 退出登录

`POST /api/auth/logout`

### 请求头

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| Authorization | string | 是 |  | `Bearer <token>` |

### 安全字段

| 项目 | 字段 |
|------|------|
| 请求签名字段 | 无业务字段，仅签 `appID`、`traceID`、`timestamp` |
| 请求加密字段 | 不参与加密 |
| 响应签名字段 | 不参与签名 |
| 响应加密字段 | 不参与加密 |

启用签名时，请求体仍需携带 `sign`；签名原文不追加业务字段，只包含 `appID`、`traceID`、`timestamp`。

### 响应示例

```json
{
  "status": true,
  "code": 1,
  "message": "退出登录成功"
}
```

退出成功后仅删除当前 token 的稳定 `sid` Hash 字段和 ZSET 索引成员，不会退出用户的其它设备；后续再次使用该 token 会返回会话失效。退出成功后会 best-effort 投递 `auth.security` 脱敏风控事件。

## 登录态失败事件

刷新、退出和其它需要登录态的接口常见失败码如下，HTTP 状态均为 `401`：

| 业务码 | 状态含义 |
|------|----------|
| 401 | 缺少 Bearer token |
| 20002 | token 已过期 |
| 20003 | token 或 JWT 声明无效 |
| 20004 | Redis session 已失效 |
| 21003 | 用户已禁用 |

需要登录态的接口会校验 HS256、issuer、AppID、JWT `sid/jti`、Redis 会话 token、过期时间、认证版本和主库用户状态；JWT `sub` 使用十进制字符串保存雪花用户 ID，`auth_version` 必须是正整数，禁止经 `float64` 转换。单表基线下主库用户按主键直查；启用拆分或迁移时仍通过身份索引定位物理表，不会删除主库 `status/auth_version` 失败关闭校验。

禁用用户、重置密码或风控封禁时，admin 必须在敏感变更事务中单调递增并提交 `user.auth_version`，再把已提交的新版本传给运行态同步接口。API 通过同槽 Lua 原子推进 Redis 认证版本并删除该用户的会话 Hash 与 ZSET；版本栅栏 TTL 覆盖 JWT 最长存活期，旧版本同步不能覆盖新版本。鉴权在 Redis 原子校验后还会查询主库状态和认证版本，因此数据库提交到 Redis 清理之间的并发请求也会失败关闭。
