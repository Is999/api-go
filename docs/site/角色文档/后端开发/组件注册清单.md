# 组件注册清单

本文档记录 `api` 默认启动组件、HTTP 路由模块和轻量运行时扩展入口。新增启动期核心组件时优先修改 `internal/bootstrap/components:DefaultSpecs`，新增 HTTP 路由模块时优先修改 `internal/handler/routes.go:builtinRouteModuleSpecs`，新增轻量运行时扩展时优先修改能力归属包的 `RuntimeRegistrySpecs`，新增启动期默认 Collector Processor 时优先修改 `collectorx.DefaultProcessorSpecs`，避免注册入口散落在 main、bootstrap、handler 或业务逻辑中。

## 统一入口

| 注册类型 | 统一入口 | 说明 |
| --- | --- | --- |
| 启动组件 | `internal/bootstrap/components:DefaultSpecs` | 单处声明核心组件来源、健康探测、关闭入口和注册清单信息 |
| HTTP 路由 | `internal/handler/routes.go:builtinRouteModuleSpecs` | 单处声明内置路由模块顺序、注册清单信息和 RouteSpecs 来源 |
| 路由规格 | `internal/handler/{domain}/routes.go:RouteSpecs` | 单处声明内置路由的 method、path、RouteMeta、接口文档、安全链路、访问日志降噪和 handler |
| 路由别名 | `internal/routealias` | 单处声明会被 RouteMeta、安全策略、鉴权事件和测试复用的稳定路由别名 |
| 路由契约 | `internal/handler/route_contract.go:DefaultRouteContracts` | 从 `RouteSpecs` 派生 method、path、RouteMeta、接口文档和访问日志降噪标记 |
| 路由元数据 | `internal/handler/shared/route_meta.go:DefaultRouteMetas` | 统一声明路由别名、访问边界和中文说明 |
| 路由安全链路 | `internal/handler/route_security_contract.go:DefaultRouteSecurityContracts` | 从 `RouteSpecs` 派生 none/public/auth/internal 安全链路 |
| 路由安全清单 | `internal/handler/route_security_manifest.go:DefaultRouteSecurityManifest` | 汇总前端同步所需的路由、链路和字段级签名加密策略 |
| 前端安全快照 | `docs/site/route_security_manifest.json` | 给前台工程同步 route policy 使用，测试会校验其与后端清单一致 |
| 启动配置校验 | `internal/bootstrap/configload:Validate` | 启动前校验基础配置、生产硬约束和安全秘钥契约 |
| 运行时扩展 | 各能力归属包 `RuntimeRegistrySpecs` | `collectorx`、`auth`、`config`、`logic` 分别声明自身轻量扩展入口；`bootstrap` 只汇总并派生清单 |

## HTTP 路由模块

| 名称 | 注册文件 | 路由规格入口 | 说明 |
| --- | --- | --- | --- |
| `health` | `internal/handler/health/routes.go` | `health.RouteSpecs` | 存活、就绪和指标路由 |
| `auth` | `internal/handler/auth/routes.go` | `auth.RouteSpecs` | 注册、登录、刷新 token、退出登录 |
| `user` | `internal/handler/user/routes.go` | `user.RouteSpecs` | 前台用户资料路由 |
| `config` | `internal/handler/config/routes.go` | `config.RouteSpecs` | 内网配置热加载状态和手动触发路由 |
| `docs` | `internal/handler/docs/routes.go` | `docs.RouteSpecs` | 内网 API 文档资源路由 |

## HTTP 路由契约

新增内置路由优先在对应模块 `RouteSpecs()` 中声明。`DefaultRouteContracts()` 和 `DefaultRouteSecurityContracts()` 会从路由规格派生，契约测试继续校验 go-zero 实际注册路由、接口文档、安全策略和访问边界，避免路由存在但文档或安全策略遗漏。

## 路由访问边界

| 边界 | 说明 |
| --- | --- |
| `public` | 公开入口，不要求前台登录态，例如健康检查、注册和登录 |
| `auth` | 前台登录态入口，必须通过 JWT 与 Redis session 校验 |
| `internal` | 内网运维入口，必须使用 `/internal/` 前缀并限制来源 IP |

## 路由安全链路

| 链路 | 说明 |
| --- | --- |
| `none` | 不经过前台签名、加密或 JWT 链路，仅用于健康检查和指标入口 |
| `public` | 经过签名和加密链路，但不校验 JWT，例如注册和登录 |
| `auth` | 必须校验 JWT 与 Redis session |
| `internal` | 必须校验 JWT、Redis session 和内网 Ops 令牌；同时显式跳过前台签名加密策略，避免运维接口被客户端签名规则误拦 |

## 路由安全清单

`DefaultRouteSecurityManifest()` 会把 `RouteSpecs` 派生出的路由契约、安全链路和 `RouteSecurityPolicies` 汇总成前端同步清单。新增或修改签名、加密字段后，必须同步 `docs/site/route_security_manifest.json`，前端 route policy 必须按该快照同步，不能自行扩大到整包、大结构体或额外字段。

## 启动配置校验

`configload.Validate()` 会在基础设施初始化前执行。`security.secret_key` 未配置时走普通请求链路；配置后必须满足 `app_id`、稳定版本、灰度版本、链路开关和 AES/RSA 材料校验，生产环境启用灰度秘钥时必须配置 `gray_salt`。

## 组件生命周期

核心启动期组件通过 `components.DefaultSpecs()` 声明组件来源，再由 `components.NewRegistry()` 注册到 `svc.ComponentRegistry`。`/api/ready` 遍历该清单执行健康探测，服务停止时按注册顺序反向释放资源。

| 名称 | 注册文件 | 注册方法 | 说明 |
| --- | --- | --- | --- |
| `mysql` | `internal/bootstrap/components/components.go` | `mysqlComponent` / `NewRegistry` | 默认主库健康探测和关闭入口 |
| `site_mysql` | `internal/bootstrap/components/components.go` | `siteMySQLComponents` / `NewRegistry` | 按名称注册扩展库健康探测和关闭入口 |
| `redis` | `internal/bootstrap/components/components.go` | `redisComponent` / `NewRegistry` | 默认 Redis 健康探测和关闭入口 |

## sys_config 约束

`sys_config` 表固定不加 `api_` 前缀。业务读取运行期配置优先声明 `SysConfigKey` 并使用类型化 getter；底层流程仍是 Redis Hash 命中优先，缺失后通过 redsync 锁保护主库回源，并写入短 TTL 空值占位防穿透。

新增业务运行期配置时优先声明 `SysConfigKey` 并通过 `GetBool`、`GetInt`、`GetString`、`GetFloat`、`GetObject` 或 `GetArray` 读取，避免业务代码散落字符串 uuid 和类型断言。

如果部署库还没有该表，只执行 `internal/database/assets/sys_config_schema.sql.tmpl`；不得新增 `api_sys_config`。

## 扩展规则

1. 新增默认路由模块：先在 `internal/handler/{domain}/routes.go` 实现 `RouteSpecs`，再在 `internal/handler/routes.go:builtinRouteModuleSpecs` 增加模块规格；`BuiltinRouteModules`、`DefaultRouteSpecs` 和 `manifest.Default()` 从模块规格派生。
2. 新增路由必须在 `RouteSpecs` 中声明 `RouteMeta`、接口文档、安全链路和 handler；别名被多个装配面复用时先补 `internal/routealias` 常量；只有 live/ready/metrics 等高频探针路由才设置 `SkipAccessLog`，不要在 access log 中间件另加路径白名单；公开路由要写清公开原因，内网运维路由必须使用 `/internal/` 前缀并限制来源 IP。
3. 新增或修改字段级安全策略后，必须运行 `go test ./internal/handler`，并同步 `docs/site/route_security_manifest.json` 与前端同名 route policy。
4. 新增启动期核心组件：先在 `components.DefaultSpecs()` 增加组件来源规格，再由 `components.NewRegistry()` 派生 `Name`、`ErrorCode`、`Check` 和 `Close`；`manifest.Default()` 会从组件规格派生注册清单，避免 ready 检查、停机释放和文档清单分散维护。
5. 新增 Collector bizType：业务动态处理器通过 `Collector.RegisterProcessor` 或 `Collector.RegisterProcessorFunc` 注册；需要启动期默认注册的内置 Processor 先维护 `collectorx.DefaultProcessorSpecs`，注册函数和运行时清单会从该规格派生。默认仍保持轻量 Collector，不引入后台 taskqueue/outbox；内置认证风控事件使用 `auth.security` 并注册默认指标 Processor，指标标签必须保持低基数。
6. 新增业务运行期配置：先声明 `SysConfigKey`，再使用类型化 getter；只有动态 uuid 场景才直接使用 `GetCachedValue(uuid)`。
7. 新增前台业务表默认使用清晰业务名；复用全局运行期配置时只允许使用无前缀的 `sys_config`。
8. 所有默认注册名称必须唯一；启动装配和 `go test ./internal/bootstrap` 会校验真实注册集合的名称冲突。
